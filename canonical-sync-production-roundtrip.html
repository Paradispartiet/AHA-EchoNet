Canonical Sync · Two-profile round-trip

Denne operatorflaten brukes til å lukke den siste dataintegritetsporten for de to allerede verifiserte production-profilene. Den aktiverer ingen ny profil og endrer ikke rollout-policy automatisk.

Én profil om gangen.

Logg inn som den pilotprofilen som skal verifiseres. Lag deretter én liten, kontrollert endring i ekte lokale AHA-data som inngår i canonical adapteren. Ikke bruk testdata som erstatter den vanlige lokale AHA-modellen.

Første kjøring skal bevise lokal endring → outbox → push → production → bootstrap/pull → lokal apply. Når den er grønn, kjører du identisk replay uten å endre data. Replay skal gi null nye endringer, null nye outbox-events og null nye pushes.

Production-endpoint og privat workspace fylles ikke inn her. Endpointet kommer fra AHA sin production-konfigurasjon, mens workspace utledes fra den innloggede Supabase-identiteten. Ingen profil-ID, workspace-ID, access token eller rå AHA-payload vises i evidence.

Denne prosedyren må bestås separat av begge eksisterende profiler før profil #3 kan vurderes.

Verifier build: hash-domains-v2. Hvis denne teksten ikke vises, skal testen ikke kjøres fordi nettleseren viser en eldre operatorflate.
